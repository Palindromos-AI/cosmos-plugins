# ZSXQ Fetch

Collect one named Knowledge Planet's complete Beijing calendar day of topics from all authors into one reader-facing Markdown file. Preserve source meaning and wording; do not summarize or analyze it. Keep verification evidence in a temporary internal audit ledger, never in the reader report.

Judge completeness by content coverage and extraction accuracy, not by source quality. Apply this rule equally to topic bodies, images, linked web pages, and PDFs: resolution, encoding, transport form, rendering path, and whether the bytes are the publisher's original file do not affect completeness when all substantive content is readable, fully extracted, and verified. Treat partial, truncated, missing, or uncertain content as failed.

## Runtime split

- Use the signed-in browser only for authentication-bound discovery, navigation, expansion, exact source capture, and visual judgment. Navigate Knowledge Planet sequentially.
- In the persistent Chrome-control session, import `collectZsxqTimelineRangeWithAutoRepair` and `collectZsxqDetailWithAutoRepair` from `scripts/zsxq-browser-collector.mjs`. These Node wrappers drive the existing authenticated tab without launching a browser, reading session storage, or calling a private API. **The collector output is authoritative**: it owns the versioned DOM adapter, mounting and readiness checks, collapsed-body expansion, sequential scrolling, exact author/time/body/attachment association, the independent dedicated-body cross-check, per-topic `image_count` with overflow-badge detection, chronology and date-boundary proof, pinned-topic safety checks, automatic repair handoff, and the resumable `browser-collector-checkpoint.json`. Submit the returned `coverage` and runner-ready `inventory` as-is; keep `browser_assets`, `pdf_download_targets`, and `skipped_topics` only as run-workspace inputs and reporting context.
- `scripts/zsxq-dom-extractor.mjs` is an internal implementation detail of the collector. Do not import it or re-run its checks manually, and never re-derive topic bodies or `image_count` by hand-written DOM inspection: a body or count the collector did not produce must never enter the runner.
- Use Node.js 22.13 or later and `scripts/zsxq-runner.mjs` as the sole owner of persistent run state, inventory comparison, identities, keys, hashes, cache admission, PDF page coverage, completeness, audit rendering, reader rendering, and safe output replacement. Node 22.13 is the first 22.x release where `node:sqlite` no longer needs the `--experimental-sqlite` flag.
- Use `scripts/zsxq-image-tiles.mjs` only when a captured image is readable at native pixels but too dense to verify reliably as one whole image; it crops lossless overlapping PNG tiles with `sharp` without resizing or inventing pixels. Sharp is lazy and optional for every ordinary runner command; if the local runtime is absent before the first tiled image, request permission and run `npm install --omit=dev` inside the installed `zsxq-fetch` directory (the lockfile pins it). Use `scripts/zsxq-single-asset-export.mjs` only for acquisition-ladder step 3, once per exact frozen `transport_url`; never pass a page-wide asset list or reuse its result for a different attachment, and visually compare the exported representation with that exact attachment's topic-local slot before accepting it.
- Before starting a run, read `references/runner-contract.md` completely. It defines the CLI lifecycle, the browser-to-runner JSON records, and the safe output-replacement rules. Do not edit `manifest.json`, the audit ledger, or the reader report by hand.
- Never let `zsxq-runner.mjs` control Chrome, inspect browser storage, or call Knowledge Planet endpoints. The browser collector may orchestrate only the already-authorized tab through the browser-control API. Node.js replaces repetitive navigation and deterministic bookkeeping, not authentication or image understanding.

## Required workflow

### 1. Resolve the workspace and request

- Read `<plugin-dir>/references/workspace-runtime.md` completely, then run `node <plugin-dir>/scripts/workspace-runtime.mjs show-config`. Configure only after the user explicitly confirms a durable root. Use the returned `<sources-workspace>` for the final report while keeping the private runner workspace temporary.
- Refuse an explicit output path outside `<sources-workspace>/output/zsxq`. Marketplace, plugin, and Skill updates never own or alter the binding or durable workspace.
- Require an exact planet name. Ask the user if it is missing or ambiguous.
- Resolve the exact named planet through the user's signed-in Knowledge Planet UI and record its canonical group URL. If multiple accessible planets share the name or the name cannot be resolved uniquely, ask the user instead of guessing. Honor an explicit planet URL only as disambiguating context; never require an owner name.
- Interpret every requested date and “today” in `Asia/Shanghai` (`UTC+08:00`), with one day running from Beijing `00:00:00` through the instant before the next Beijing midnight. Honor an explicit date; otherwise call the bundled `currentBeijingDate()` helper in `scripts/zsxq-time.mjs` to resolve the current Beijing calendar date. Treat Knowledge Planet's displayed timestamps as Beijing time and fail closed if visible platform evidence contradicts that contract. Record the resolved `YYYY-MM-DD`; never substitute the computer, browser, user-location, or publisher timezone.
- Default the output to `<sources-workspace>/output/zsxq/YYYY-MM-DD-<planet>.md`; honor only a workspace-contained explicit output path. Replace `/`, `\`, and control characters in the planet-derived filename with `-`.
- Include every topic published in the resolved planet on the requested date, regardless of author, and preserve each topic's exact displayed author. Exclude comments, replies, likes, and other interactions.
- Do not schedule future runs or add a generated summary.

### 2. Use the authenticated browser safely

- Follow the available Chrome-control skill and operate the user's existing signed-in Chrome session.
- Never inspect or export cookies, local storage, browser profiles, passwords, or session files.
- If Chrome is not connected or Knowledge Planet requires authentication, stop and ask the user to connect Chrome or sign in there. Do not bypass authentication with search results, previews, another account, or a private API.
- Keep the remote session read-only: do not post, comment, react, follow, edit, or delete anything.
- Always use the collector's `WithAutoRepair` exports in a skill run. DOM-contract failures and internal runtime reference failures return `automatic-repair-required` with the failure `code`, `phase`, and a sanitized diagnostic handoff; invalid input, permission, authentication, browser-connection, and external-service errors remain direct actionable errors because adapter repair cannot resolve them. When automatic repair is required, immediately show the returned `notification` as a non-blocking progress update, retain the workspace, read `references/browser-repair-playbook.md` completely, diagnose and repair from evidence, run every required validation, and resume from the retained browser and runner checkpoints. Do not pause for repair approval. Repair permission never grants permission to commit, merge, push, publish, install dependencies, bypass access controls, or make unrelated changes.
- Two collector error codes are deliberate hard stops, not repair targets: `STICKY_TARGET_DATE_UNSUPPORTED` (see step 3) and `DETAIL_IMAGE_GALLERY_OVERFLOW_UNSUPPORTED` (a linked detail page whose image gallery shows a `+N` overflow badge; record that page's child inventory as failed through `inventory_failure` instead of repairing).
- Create a private temporary parent directory, choose a unique child path that does not yet exist, and pass that child to the runner's `init` command; the runner atomically creates and owns the workspace — never pass an existing empty directory or symbolic link. Keep the inventory, raw transport URLs, working text, audit ledger, cache, and every captured representation there; every JSON input and referenced representation must resolve inside this workspace without symbolic links to outside paths. Use `assets/extraction-audit-template.md` for the temporary audit ledger and never place it in `output/`. The runner removes the marked directory after successful verification; on failure, retain it only when it helps diagnosis and report its path without exposing signed URL parameters.

### 3. Prove timeline coverage

- In the official UI, inspect and clear stale searches, tags, “只看星主”, member filters, and every other topic filter so the timeline includes every author's topics. Only after that visible confirmation, call `collectZsxqTimelineRangeWithAutoRepair` with `filtersClearedConfirmed: true`, the exact planet name, canonical group URL, Beijing platform date, runner workspace, and the live tab. Never set the flag merely to bypass `needs-filter-confirmation`; that status means the browser inventory is not allowed to start. The collector scrolls from the verified top until either the oldest stable timestamp is below the requested date or one exact direct `没有更多了` marker proves the absolute end of the finite timeline.
- When the collector returns `needs-top-confirmation`, visually load or dismiss every pending new-content batch through the official UI, confirm none remains, then rerun it with `topBoundaryConfirmed: true`. Never infer this confirmation from elapsed time or set the flag merely to continue. A visible top newer than the target date is already a sufficient upper bound; a top equal to or older than the target date requires this confirmation first, and only afterward may an older top prove a zero-topic target date.
- Require `status: complete` and proof that the stream crossed below the requested date before submitting the returned `coverage` and complete `inventory` object to the runner. Its exact top-level shape is `{ "topics": [...] }`; pass that object directly to `record-inventory`, never `inventory.topics`, and do not reconstruct or clean it by hand. Use `browser_assets` to target exact image capture and `pdf_download_targets` to drive official PDF downloads; signed sources remain in the temporary workspace.
- Pinned topics are archived only through their normal position in the non-pinned stream. If a pinned topic's publication timestamp belongs to the target date and no matching stream topic proves it is also rendered there — or a pinned timestamp cannot be read at all — the collector stops with `STICKY_TARGET_DATE_UNSUPPORTED`. This is a documented platform-behavior limitation, not an adapter defect: report to the user that the day cannot be archived completely while that topic stays pinned, and do not enter the repair workflow.
- Timeline topics whose image gallery shows a `+N` overflow badge (more images than the timeline preview renders) are excluded from the inventory by decision and returned in `skipped_topics` with author, timestamp, and reason; the coverage evidence records the skip count. Report every skipped topic to the user in the final response. Do not treat the badge as a defect and do not attempt manual enumeration for the skipped topic.
- Displayed timestamps must parse strictly (`YYYY-MM-DD HH:mm[:ss]`, Beijing) everywhere they can affect the result: the timeline top, every target-date candidate, and every topic above the proven crossing below the target date. An unreadable timestamp strictly below that crossing can no longer affect membership, boundary, or chronology and is tolerated. Image-readiness checks likewise gate only target-date topics, so a broken thumbnail in an unrelated day cannot stall the run.
- Submit the collector's complete source-inventory object once with `record-inventory`; the accepted top-level inventory is frozen, so start a new run rather than replacing it if that inventory was wrong, and do not start attachment extraction until the runner accepts it. Supply the raw stable platform identifier or permalink and let the runner derive each `topic_key`. The runner converts every explicit timestamp offset to `Asia/Shanghai` before determining its calendar date; every topic must fall on the requested Beijing date and the inventory must be newest first by instant. For `present` bodies, the runner stores SHA-256 of the exact UTF-8 bytes; `empty` and `failed` store no body hash.
- Persist each attachment as a separate inventory entry with type, source ordinal, filename when exposed, stable platform identifier when available, and a transient `transport_url` when downloading requires one; supply every available raw value. The runner derives `sanitized_source_url` by removing the complete query and fragment; keep the full transport URL only in the temporary workspace. Derive `source_identity` through the runner from the first available value in this order: `platform-id:<exact-id>`, then `url-sha256:<hex>` over the sanitized (query- and fragment-free) transport URL, then `binary-sha256:<hex>`, then `no-source-identity`. Identity and inventory comparison never use the signed URL form, so signed-URL rotation between sessions cannot break a resumed run. Never provide a precomputed identity or use a lower-priority identity when a higher-priority value is available.
- Associate every top-level image with one inventoried target-date topic before acquiring it, proven from that topic's own container, permalink/detail view, attachment order, or equivalent visible UI relationship. Never treat a page-wide asset inventory, a shared `images.zsxq.com` host, or the current scroll viewport as association proof. Exclude assets of other topics, avatars, group artwork, navigation, and other interface chrome before any screenshot or export.
- Every occurrence key is runner-derived as `<topic_key>:<type>:<source_ordinal>:<source_identity>`, even when the same platform ID, URL, or binary appears in another topic. Counts or arbitrary keys alone are not coverage proof.
- Within a linked page's main content, inventory every substantive inline image and directly embedded PDF as a child of that page attachment, following the one-time `record-web-inventory` rules in `references/runner-contract.md`: during the page's single visit, first prove the complete child count with page-end/main-content evidence, then freeze the child inventory before extracting the page body or any child. For a Knowledge Planet detail link, call `collectZsxqDetailWithAutoRepair` and include every returned `files` entry in `dom_ordinal` order; a detail page's strict PDF cards are embedded children, never ignorable decoration. Submit a zero count only for a verified child-free page; when the complete range cannot be proven, submit `inventory_failure` with a concrete reason and localized reader note instead of claiming zero. Treat decorative icons, avatars, navigation graphics, ads, and recommendation thumbnails as interface noise, and do not recursively follow hyperlinks discovered inside the page.
- For timeline topics, `image_count` and `image_count_evidence` come from the collector's verified gallery accounting; never re-count by hand.
- If the newest boundary cannot be established, the timeline cannot load far enough, chronology is inconsistent, or access hides an unknown number of topics, stop without creating or replacing the final file. Report why completeness cannot be established. A verified zero-topic day is valid only after crossing below the requested date.
- Submit the visible boundary evidence through `record-coverage`. A false coverage field requires a specific failure reason; `finalize` then fails closed and writes no report.

### 4. Minimize repeated work

- Treat browser navigation as the scarce step. When opening a linked page, expand through the complete main-content boundary, submit its frozen child inventory, then capture its body, metadata, and exact assets before navigating away. The inventory call and extraction remain separate runner states but occur during one browser visit. Do not revisit that page solely to collect information or assets that were available during the first visit.
- Treat a browser asset list as inventory, not as a download queue. Never call an asset bundle with more than one remote image asset ID, never bulk-export every image on a page, and never select image downloads only by host, filename pattern, or rendered dimensions. Use a remote acquisition route only when the active tool provides an enforceable per-call deadline or cancellation; a request timeout that cannot cancel the underlying remote fetch is not enforceable.
- Use this per-image acquisition ladder: (1) the rendered topic preview or a locator screenshot of that exact image; (2) after one click into the platform image viewer, a locator screenshot of the clearer rendered image, rechecking the open viewer's exact image source and topic-local ordinal after the click; (3) one exact single-asset export through `scripts/zsxq-single-asset-export.mjs`. Stop acquiring at the first representation whose native pixels contain the needed information. If a clearer attempt fails or times out, do not retry alternate signed URLs, original-file variants, or equivalent transformations; retain the best already captured representation.
- When the native image contains small or dense text but whole-image visual verification remains uncertain, run `scripts/zsxq-image-tiles.mjs` against that exact workspace-local representation under the tile rules in `references/runner-contract.md`. This tile pass is mandatory before failure: never mark an image failed for small, dense, or compressed text while its native pixels have not yet been read tile-by-tile. Read every tile once in row-major order, reconcile duplicated text only inside the overlap, merge the semantic payload in natural reading order, and submit `tile_manifest_path` plus one ordered `tile_verifications` entry per planned tile; if any tile remains unreadable, the image is failed. Never upscale, sharpen, denoise, or otherwise manufacture pixels — tiling improves visual attention, not source information.
- Keep one in-run binary cache through the runner's `cache-lookup` command. Reuse image or PDF extraction only when the representation or binary SHA-256 matches and the cached extraction is complete and verified; never reuse a failed, partial, or uncertain result. There is no page cache: a repeated linked page is revisited and extracted again. Keep every occurrence-specific key in the audit ledger even when its verified payload is reused.
- Navigate authenticated pages sequentially so the browser session and timeline state remain deterministic. After source assets are local, independent images and PDF pages may be processed in bounded parallel batches, hashing and verifying each result separately.
- On a clearly blocked external page, stop retrying after the normal clean-page route and the one permitted browser route have both produced the same access-control result; record the failure and continue with the remaining inventoried content.
- These optimizations may remove duplicate navigation, download, OCR, and hashing work only — never reduce the inventory, skip an attachment, weaken verification, or change the one-level linked-page boundary.

### 5. Extract each topic in source order

Process the inventoried topics newest first, matching their source order. After freezing every linked-page child inventory for the topic and finishing all top-level and embedded extraction, write its JSON record according to `references/runner-contract.md` and submit it with `upsert-topic`; the runner accepts only the next source-order topic or a correction to the latest one, compares it with the frozen inventories, hashes every referenced file and payload, and atomically checkpoints the manifest. Use an ISO-8601 date-time with an explicit `Z` or numeric UTC offset. Use `status` after each topic to find pending child inventories and the resumable topic position.

For the topic body:

- Copy only the exact body carried by the collector's frozen inventory; the collector already cross-checked it against its dedicated extractor. Never "clean" a frozen body, re-extract it by hand, or let the runner infer whether a phrase is UI. The `展开全部`/`收起` control text is structurally excluded by the collector; identical text inside the body is legitimate source content.
- Copy all visible text without summarizing, translating, correcting, or stylistically rewriting it. Preserve headings, paragraphs, lists, quotations, and link targets when the source exposes them. Mark source text that is genuinely unreadable as `[无法辨认]`; never guess.
- Set `body_status: present` only after the complete displayed body has been captured. A truncated, partially hidden, or uncertain body is `failed` regardless of how much text was recovered.
- When a body is `failed`, store any reliably recovered source fragment separately from `failure_reason`; store its exact UTF-8 `recovered_payload_sha256`, or no recovered hash with the literal `无可可靠恢复内容` when no fragment can be trusted. Never mix the failure explanation into the source payload.

For each image, in attachment order:

- Use any representation available through the platform's official UI that makes all substantive image content readable — preview, thumbnail, transformed image, browser-rendered image, or page screenshot. Prefer a clearer representation only when the current one leaves content unreadable or uncertain; do not spend time retrieving the publisher's original binary when the complete content can already be verified. Record the used representation's exact pixel dimensions, SHA-256, and `representation_type` per `references/runner-contract.md`; these fields identify evidence and never grade quality or completeness.
- Extract the image's semantic content text in natural reading order: text a downstream reader needs to understand what the author intended to share. Exclude unrelated interface chrome (status bars, viewer controls, follow/share buttons, navigation labels, comment placeholders, standalone interaction counts); keep interface text only when it is itself material evidence (a discussed setting, an error message, a transaction value, a tutorial step). When uncertain, include rather than delete potentially substantive text. Keep a displayed account name or watermark as `source_account` metadata (`未显示` when absent), never inside the OCR payload. Preserve visible paragraph, list, and table structure. Write `未检测到可读文字` for an image with no readable text, and record a specific extraction failure instead of silently omitting an inaccessible image.
- Perform a separate visual verification pass against the same representation used for extraction: confirm every content region is captured, structure preserved, `source_account` separated, and interface chrome absent. If the representation is too degraded, cropped, or obstructed to prove this, obtain a clearer representation; when the obstacle is small or dense text over sufficient native pixels, run the mandatory tile analysis before failing.
- Set `verification_status: verified` only when that comparison succeeds, regardless of representation quality or transport form; otherwise set it `failed` with the exact missing or uncertain content. `extraction_status: present` requires a complete OCR payload; `empty` requires visually verified absence; partial OCR is `failed`. If no representation can be acquired at all, omit the representation fields and record failed extraction plus failed verification so the runner retains the known attachment as incomplete. For `failed`, keep any reliably recovered fragment separate from `failure_reason`, with its `recovered_payload_sha256` or the literal `无可可靠恢复内容`.

For each linked web page:

- Prefer the available clean-webpage extraction skill for public HTML pages; use the authenticated browser only when the page requires its existing session or interactive rendering. Any accessible rendering is acceptable (clean-page extraction, browser rendering, reader view, screenshot/OCR); never substitute a search snippet or another publisher.
- Extract the article title, original linked URL, canonical URL when available, visible author/publication metadata, and main body. Remove navigation, advertisements, cookie banners, recommendations, and unrelated comments; preserve the page's semantic heading, paragraph, list, quotation, and table order.
- Extract the frozen child inventory's inline images and embedded PDFs with the image and PDF rules above, keeping their payloads and evidence separate from the page body; complete body and children in the same browser visit whenever the UI exposes them together, reusing the in-run binary cache for identical binaries.
- Persist `web_body_status` under the same `present`/`empty`/`failed` rules as image text: `present` only for the complete substantive body and structure; clipped, paginated-but-unloaded, or paywalled bodies are `failed`. The page's aggregate `extraction_status` is `present` only when the body is `present` or `empty` and every inventoried child is complete and verified; otherwise the page is `failed`, retaining recovered fragments, hashes, and `failure_reason` as separate audit fields.

For each PDF:

- Follow the available PDF skill.
- Treat blocked inline viewing and blocked downloading as different states. When the official file preview exposes exactly one visible `下载文件` control for the inventoried filename, call `downloadZsxqTimelinePdfOnTab` with that occurrence's `dom_topic_index` (as `topicDomIndex`), `file_ordinal` (as `fileOrdinal`), and expected filename taken from the collector result's matching `pdf_download_targets` entry — never guess or re-derive these indices from the page. Arm the browser download event before clicking, resolve the exact completed download rather than guessing from its filename, and copy it into the private runner workspace before parsing. If the file card no longer matches (`PDF_FILE_IDENTITY_MISMATCH`), re-collect instead of guessing. Use only this official member UI; never reverse-engineer private APIs. Record a document-level access failure only when neither an official download nor another complete accessible representation exists.
- Use whichever accessible representation yields complete page contents (text layer, rendered pages, screenshots, OCR); prefer the text layer, then visually check any page whose extraction is missing, incomplete, or corrupt. Establish the total `page_count` independently (parser, metadata, viewer total, or another reliable end signal) with `page_count_evidence`; an unprovable or disputed total makes the PDF failed.
- Preserve page boundaries as `#### 第 N 页` (top-level) or `##### 第 N 页` (embedded) in reading order, record unreadable pages explicitly, and persist one entry per page under `references/runner-contract.md`; a missing, duplicate, out-of-order, or out-of-range page makes the PDF failed. If no page representation is acquirable, record one `document_failure` and retain `page_count_evidence`. Failed pages keep recovered fragments separate from `failure_reason`, with `recovered_payload_sha256` or `无可可靠恢复内容`.

### 6. Build the reader report through the runner

- Run `finalize`; do not compose either artifact manually. Before rendering, the runner resolves and re-hashes every checkpointed source binary and representation; a missing, redirected, or changed file stops with no output and leaves the workspace resumable. It then renders the temporary audit ledger (schema illustrated by `assets/extraction-audit-template.md`) and the reader report, and applies the safe output-replacement rules defined in `references/runner-contract.md` — marker-scope checks, newer-snapshot refusal, atomic same-directory replacement, and stale-partial cleanup. The audit ledger is process evidence, not user content.
- The runner uses `assets/daily-source-template.md` as the reader-report contract: one section per inventoried topic and one subsection per attachment in original order, showing only the planet name, date, topic author and timestamp (rendered as Beijing time `YYYY-MM-DD HH:mm:ss`), unchanged topic body, original content links, linked-page author or publication time when displayed, and extracted image, webpage, and PDF contents.
- The reader report is generated exclusively from those whitelisted content fields: internal paths, keys, identities, platform IDs, ordinals, image counts or evidence, raw or sanitized asset URLs, hashes, dimensions, status fields, page-count evidence, and verification notes are never part of its template. Keep the linked page's original URL in its heading because the shared link is part of the source content; never expose image or PDF transport addresses.
- For a failed item, the reader report copies any reliably recovered fragment into its normal section, adds one short bracketed reader note at the exact missing location (such as `[原图文字过小，部分内容无法可靠辨认]`), and lists the affected items under `未能完整读取的内容` with the reader-relevant reason only — no OCR passes, hashes, browser paths, or retries.
- The report ends with exactly one runner-added hidden `zsxq-fetch` marker (planet name, canonical planet URL, date, snapshot time, topic count, completeness) supporting safe reruns. For a verified zero-topic day, the report retains only the title and hidden marker. Source payload text is never rejected merely because it contains comment syntax or words that resemble audit labels.
- `completeness: complete` requires proven timeline coverage, every inventoried topic and attachment accounted for, every substantive payload fully extracted, and every image `verification_status: verified`. Source resolution, file fidelity, and acquisition route are never completeness gates; visual verification belongs to this extraction skill and must never be deferred downstream. When coverage is proven but any known item failed, the runner writes `<resolved-output-stem>.incomplete.md` instead and never overwrites a complete canonical report. `post_count` is the number of matching topics, including zero.

### 7. Verify and report

The runner performs verification during `upsert-topic` and `finalize`; do not duplicate it through hand-built Markdown or hand-computed hashes. Its actual guarantees are:

- At `upsert-topic`, every extracted topic is compared field-by-field with the frozen source inventory: topic key, author, full timestamp, body status and applicable body or recovered-payload SHA-256, image count and evidence, attachment types, ordinals, image ordinals (`1..image_count` exactly), association evidence, platform IDs, sanitized transport URLs, PDF filenames, and every frozen webpage-child inventory (count, types, ordinals, IDs, sanitized URLs, filenames). Keys and identities are always derived by the runner — a lower-priority identity is rejected when a higher-priority value exists — and PDF pages must appear exactly once in order `1..page_count`.
- At `finalize`, every checkpointed source binary, representation, and tile file is re-resolved and re-hashed; any change stops finalization with no output. The audit ledger is rendered from the verified manifest, written to disk, and its disk round-trip must equal a fresh rendering byte-for-byte; the runner additionally requires every runner-owned resource address in the manifest to be the query- and fragment-free `sanitized_source_url`. It does not scan rendered payload text for label-like lines, so source content can never be falsely rejected as a leak.
- The reader report is not diffed against the audit ledger; both are rendered from the same verified manifest, and the reader template is restricted to the whitelisted content fields listed in step 6. That construction — not a post-hoc comparison — is what keeps process metadata out of the reader report.
- The runner inspects the reader report's hidden marker and applies the rerun-safety rules from `references/runner-contract.md` before replacing any file, then deletes the temporary audit ledger and cache after success.

In the final response, report the resolved Beijing platform date, planet name, topic count, completeness value, extraction-failure count, every `skipped_topics` entry (author, Beijing timestamp, and that it was skipped for an image-gallery overflow), and the clickable absolute output path. Do not add a summary of the collected content.

## Hard rules

- Keep collected content local. Never publish, upload, email, or message it.
- Never use an unofficial Knowledge Planet API, reverse engineer requests, or introduce credentials.
- Never claim completeness unless an older topic or the exact absolute timeline-end marker proves the lower boundary and every inventoried item was accounted for.
- Never silently omit failed or ambiguous content. The only permitted exclusions are the collector's explicit `skipped_topics` (image-gallery overflow), and each of them must be reported to the user.
- Never render verification metadata in the reader report. Keep paths, keys, identities, hashes, dimensions, statuses, page-count evidence, verification notes, and image/PDF transport addresses in the temporary audit workspace only.
- Never render, report, or retain beyond the temporary workspace a full signed image or PDF transport URL, including its query, token, signature, or fragment.
- Never reject an otherwise complete extraction solely because its source representation is lower quality, transformed, browser-rendered, or not the publisher's original file.
- Never delegate image-to-OCR verification to a downstream analysis agent.
- Never include comments or replies. Changing that boundary requires updating this skill's agreed scope first.
- Never interpret a requested day through the computer, browser, user-location, or publisher timezone; every ZSXQ day is fixed to `Asia/Shanghai` (`UTC+08:00`).
- Automatically diagnose and repair browser-contract or collector-internal runtime exceptions after notifying the user with a non-blocking progress update. Preserve diagnostics and checkpoints, validate the repair fully, and resume from the retained position. Never commit, merge, push, publish, bypass access controls, or change unrelated files without separate authorization. The sole exception is `$fix-report` operating on its independently configured repository for the specified report-only commit and push.
