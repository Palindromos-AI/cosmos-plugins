# ZSXQ Fetch

Collect one named Knowledge Planet's Beijing calendar day — or one contiguous range of days merged into a single report — from all authors into one reader-facing Markdown file, optionally filtered by a user-supplied information requirement. Preserve source meaning and wording; do not summarize or analyze it.

## 1. Resolve the workspace and request

- `<sources-workspace>` is the fixed `~/Documents/cosmos-workspace/sources`; `node <plugin-dir>/scripts/workspace-runtime.mjs show-workspace` prints its absolute path and creates the tree when missing (`<plugin-dir>` is two levels above this `SKILL.md`).
- Require an exact planet name; resolve it through the user's signed-in Knowledge Planet UI and record its canonical group URL. If the name is missing or resolves ambiguously, ask the user instead of guessing.
- Interpret every requested date and “today” in `Asia/Shanghai` (`UTC+08:00`); accept one explicit date or one contiguous range of at most 31 days whose end is not in the future (a range whose start equals its end is a single-day request), otherwise resolve the current Beijing date with `currentBeijingDate()` from `scripts/zsxq-time.mjs`. Treat Knowledge Planet's displayed timestamps as Beijing time.
- A natural-language filter is optional. Without one, archive every topic. With one, choose a stable semantic `<scope-key>` (reuse it when later wording means the same thing) and record the original wording; never use the raw sentence as identity.
- An extraction scope is optional. Extract everything by default; the user may state a natural-language extraction requirement — excluding attachment content types（图片 `image`、链接页面 `web`、PDF `pdf`、HTML `html`、Word `word`，例如“不要图片”，“只要文本”即排除全部五类）, or a judgment rule such as keeping only one version of a document a topic carries in several forms. Choose a stable semantic `<extract-key>` (reuse it when later wording means the same thing) and record the original wording; map type exclusions onto those exact type keys. Topic body text is always extracted.
- Default the output to `<sources-workspace>/output/zsxq/YYYY-MM-DD/<planet>.md` for a single date and `<sources-workspace>/output/zsxq/ranges/<start>_to_<end>/<planet>.md` for a range; a filtered run appends the derived short filter name, `<planet>-<short-filter-name>.md`, and a run with an extraction scope additionally appends a short derived scope name（例如 `-不含图片`、`-仅文本`、`-单一版本`）. Honor only an explicit filename in that exact directory; replace `/`, `\`, and control characters in the derived filename with `-`.
- Treat the canonical planet URL — plus the stable filter `<scope-key>` when a filter is applied, plus the stable `<extract-key>` when an extraction scope is set — as the collection identity and the planet name as mutable display metadata.
- Create one private temporary directory (`mktemp -d`) for day JSONs, downloads, and captured images; keep collected content there until publication and remove it afterwards.

## 2. Collect each day from the browser

- Follow the available Chrome-control skill and operate the user's existing signed-in Chrome session, read-only: never post, comment, react, edit, delete, or inspect cookies, storage, or credentials. If Chrome is not connected or Knowledge Planet requires authentication, stop and ask the user.
- In the official UI, first clear stale searches, tags, “只看星主”, member filters, and every other topic filter so the timeline includes every author's topics.
- In the persistent Chrome-control session, import the collector from `scripts/zsxq-browser-collector.mjs` and call `collectZsxqTimelineRangeOnTab` once per requested date with the exact planet name, canonical group URL, and Beijing date; `references/runner-contract.md` documents its API.
- **Collector outcomes**: a collector error is a direct error carrying a content-free `code` and `phase`, and a successful collection can still return topics it could not fully cover. Handle each outcome as follows.
  - Stop the run only for what the user must resolve — Knowledge Planet authentication, permission, and connection errors — and for a failed timeline collection, whose DOM-contract mismatch is a repair decision.
  - Fail only the item when a per-item step errors — an official file download, a detail-page collection (including its `DETAIL_IMAGE_GALLERY_OVERFLOW_UNSUPPORTED` gallery overflow), or a single-asset export — under the per-item failure rule in step 3, and keep collecting.
  - Report, in the final response, every topic returned in `skipped_topics` — topics skipped for a `+N` image-overflow badge; they do not enter the day JSON.
  - Record and report every entry in `unproven_sticky_topics` — a pinned topic whose target-date rendering cannot be proven in the stream, or whose pinned timestamp cannot be read: keep collecting, copy each entry into the day JSON's `unproven_sticky_topics` with a short reader note saying the topic may be missing, and name every one in the final response.
- A multi-day range is collected as one day at a time, end date backward to start date, each producing its own day JSON.

## 3. Extract attachment content

- **Extraction scope** (when set): apply the requirement with judgment before extracting. A type exclusion skips every attachment of that type — do not open, click, download, read, or export it, including that type inside a linked page's `embedded_media`. A version rule keeps exactly one representation when one topic visibly carries the same document in several forms（如中英文版与图片版）: follow the user's stated preference, defaulting to the Chinese version, and to a text form over an image form of the same content; inspect the candidates only enough to decide, and extract everything when it is uncertain whether they are the same document. Whatever the extraction scope omits is left out of the day JSON entirely — it is not a failure, never makes the report incomplete, and is not disclosed in the report.
- **Charts**: never read a chart or graph — a bar, line, pie, candlestick, or similar data visualization — including its axis labels, legends, and other incidental text. An image that is only a chart, and a file or linked page whose content is only charts, is left out of the day JSON on the same terms as an extraction-scope omission — not a failure, never incomplete, not disclosed; inspect it only enough to decide. An image, file, or page that also carries substantive text keeps that text and drops the charts.
- **Images**: acquire the image file, read it locally, then decide.
  - Associate: open the platform viewer for the exact topic attachment and verify its image ordinal. The viewer is only for locating and loading the image file, not for screenshot transcription. Do not use thumbnail or screenshot pixels as an extraction path. Record the actual loaded image dimensions; larger pixel dimensions alone do not establish better source quality.
  - Acquire in this order, advancing only when the previous method is unavailable or fails to produce the correctly associated, complete image file. Stop after the first successful acquisition; do not download the same version again merely because its text looks blurry. Respect user restrictions, system permissions, and the authentication/permission/connection stop rules above.
    1. Browser resource export: use the supported `pageAssets` capability after the viewer has loaded. Read its documentation, inventory the current page, match only the exact current viewer image, and bundle that asset alone. Never export the whole page's resources or infer an image from a filename alone.
    2. Browser image download: use the supported `downloadMedia` operation on that exact viewer image, or the browser's visible image-download control. Verify the download destination and its association with the current attachment; do not confuse an old file or another simultaneous download with this one.
    3. Existing export script: call `scripts/zsxq-single-asset-export.mjs` with the exact image URL actually provided by the current page/viewer. Never guess, strip, or change URL parameters, discover a private endpoint, or introduce credentials. Keep signed URLs in memory or temporary run files only, never in logs or the reader report.
  - Read: verify the saved file is complete and matches the attachment, then read its substantive text at native resolution in natural order, excluding interface chrome. If needed, split that file with `scripts/zsxq-image-tiles.mjs` and read every lossless tile over the full image with overlaps merged once; never upscale, sharpen, or generate replacement pixels. If sharp is missing, install the pinned dependency from the skill-local lockfile by running `npm install --omit=dev` in the skill directory — this needs no separate approval — then retry the tiling; if the install itself fails, record the item as `failed` with the dependency failure in `reader_note`, keeping any reliably read fragments as `recovered_payload`, and continue.
  - Decide: if every permitted acquisition method fails, record this attachment as `failed` with the actual acquisition cause in `reader_note`, then continue other items. Missing tiling support or a file-reading failure is not proof that the source is blurry. Claim source-quality unreadability only after inspecting the acquired file at native resolution, using tiles when necessary; retain reliably read fragments and do not invent missing text. Do not put failure explanations in `payload`.
  - Cleanup: keep files and any export manifests in the private run directory. If a browser tool writes to its own temporary directory or Downloads, track that exact output, move the required file into the run directory, and remove only the artifacts created by this run after publication, including manifests containing signed URLs. Report blocked cleanup rather than claiming it succeeded.
- **Linked pages**: capture the title, original URL, metadata, complete main body, and the page's own substantive images, PDFs, and HTML and Word files as `embedded_media`. For a Knowledge Planet detail link, use `collectZsxqDetailOnTab`. Read any other link through these routes in order, advancing only when the previous one is unavailable or fails to return the page's main body — a sign-in prompt, paywall stub, anti-bot page, or other content that is plainly not the article counts as failing to return it:
  1. The clean-webpage extraction skill, when installed, on the original URL.
  2. The user's signed-in Chrome: open the original URL once in a new tab of the current Chrome-control session, read the rendered main content read-only, then close that tab.
  A page neither route can read is recorded as `failed` with a reader note naming the cause, and the run continues. A sign-in wall, paywall, or refusal on a linked page is such a cause — it is not the Knowledge Planet authentication stop of step 2 — so never ask the user or wait for them there. Name every unreadable linked page in the final response, original URL and cause, sign-in requirements first, so the user can sign in and rerun.
- **Link depth**: extraction reaches exactly one hop from the topic. That hop is what the topic itself carries: each link in the topic body, opened as a linked page, and the PDF, HTML, and Word files attached to the topic. A linked page's own media belong to the same hop and are read as `embedded_media` — an image it displays, a document it embeds, or a direct link whose target is a PDF or Word file rather than another web page. Nothing else is followed: a link to another web page inside a linked page, and every link inside a PDF, HTML, or Word file or inside an image — whatever it points to, including Knowledge Planet, a file, or an image — is recorded verbatim in the extracted text, link text and URL, and never opened, downloaded, or resolved. A signed transport URL is recorded by its link text alone, as the hard rules require.
- **PDF, HTML, and Word files**: acquire only through the official member download using the collector's `file_download_targets` and the matching downloader — never a private API. The downloader closes every opened file preview by clicking outside its content and proves the source page remains before the tab is reused; do not add another preview or tab lifecycle around it. Copy the download into the temporary directory and extract it with the available PDF skill (preserving `第 N 页` page boundaries); for HTML, by reading the document structure without executing scripts or loading remote subresources; for Word (`.doc`/`.docx`), by converting the document to text with an available document-reading tool, preserving reading order and never executing embedded active content.
- **Filter** (when given): judge each topic's relevance from its body before extracting attachments; exclude a topic only when it is confidently unrelated, prefer recall, and always select topics whose relevance is uncertain or whose body is unreadable. Leave excluded topics out of the day JSON and count them in `excluded_topic_count`.
- Record whatever could not be downloaded or reliably read — a failed official file download, an uncollectible linked or detail page, an unreadable image — as `failed` with a reader-facing note, then continue with the remaining attachments and topics; a per-item failure never stops the run. Never guess unreadable text, and never mix a failure explanation into a `payload`; it belongs in `reader_note`.

## 4. Publish through the runner

- Assemble one day JSON per collected date in the exact shape defined in `references/runner-contract.md`, then run `zsxq-runner.mjs publish --input <day.json> --output <target>` for a single day, or `publish-range` with every day's JSON plus `--start`/`--end` for a merged range. Do not compose the report by hand.
- The runner renders the reader report in its own fixed format, appends the hidden identity marker, derives completeness, and atomically replaces only a same-identity generated file under the cross-process lock; an incomplete report is written to the `.incomplete.md` sibling instead.
- Process metadata — paths, IDs, URLs other than a linked page's original URL, counts, statuses — never enters the reader report. A URL that is part of the source text itself is content, not metadata, and stays in the payload, minus any signed transport query as the hard rules require.
- In the final response, report the resolved date or range, planet name, extraction scope when set, rendered topic count, filter-excluded count when filtered, completeness, extraction-failure count, every skipped topic (author, Beijing timestamp, overflow reason), every unproven pinned topic, every linked page that could not be read (original URL and cause, sign-in requirements first), and the clickable absolute output path. Then remove the temporary directory.

## Hard rules

- Never use an unofficial Knowledge Planet API, reverse engineer requests, or introduce credentials.
- Never render, report, or retain beyond the temporary directory a full signed image, PDF, HTML, or Word transport URL, including its query, token, signature, or fragment.
- Never include comments or replies.
- A repair means editing installed skill files or deviating from this document's procedure. Before repairing, tell the user the confirmed cause and the smallest intended change, and repair only after their explicit approval; if the user declines, change no installed file and report the failure. Never commit, merge, push, publish, install dependencies (other than the pinned `sharp` from the skill-local lockfile when image tiling needs it), bypass access controls, or change unrelated files without separate authorization. The sole exception is `$fix-report` operating on its independently configured repository for the specified report-only commit and push.
